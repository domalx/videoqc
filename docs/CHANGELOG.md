# 更新记录

一条一行，只写改了什么、优化了什么。

## v0.3.5 · 2026-11-25

- **`run_decode_pass` 拆开**：172 行的单函数拆成拼命令、拉进程、采样配对、收尾四段（`media/runners.py` 323 → 252 行）。
- **stderr 文案解析独立成 `media/stderr_parse.py`**：正则与事件状态机集中一处，升级 ffmpeg 只需改这个文件。
- **`analyze_file` 拆开**：146 行拆成 `_stage_probe` / `_stage_packets` / `_stage_decode` / `_run_detectors` / `_resolve_status`，编排层只留顺序、取消与状态。

## v0.3.4 · 2026-11-24

- **剪辑成片不再被判成录制损坏**：音频在同一位置也断开 ⇒ 降为 medium「疑似剪辑/重封装」，只有视频单边断才判 high。
- **坏包/解码报错能定位到时间**：D12 给出首末时间与最密集的 5s 窗口，问题点可直接跳过去看。
- **画面采样 5s → 1s**：短于 5s 的绿屏、闪白、纯色不再漏检；「连续 N 个采样点」这类判据全部改成按秒，阈值不再随采样网格漂移。
- **像素级噪声收敛**：尾部截断不再被当成 high 缺帧，单帧暗部/纯色不再各生成一条 low。
- **CI 起来了**：`windows-latest` 上下 ffmpeg、生成 `tests/data` 夹具再跑 ruff/mypy/pytest，夹具与 `bin/` 仍不入库。
- **健壮性**：点停止后的迟到结果不再冒出第二轮「扫描完成」；无音轨文件不再把字幕流当音频统计。
- **读包少取一列**：`duration_time` 没有任何检测项使用，去掉后同文件 CSV 体积 −24%（1.97MB → 1.50MB），墙钟时间不变。
